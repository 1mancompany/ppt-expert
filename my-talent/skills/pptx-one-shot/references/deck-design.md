# Deck Design Reference

Use this reference when designing the narrative, visual system, slide mix, and page layouts.

## Narrative Defaults

Infer the deck type from the request:

- **Pitch / product**: problem, insight, solution, product, proof, market, model, roadmap, ask.
- **Business report**: context, objectives, progress, analysis, risks, decisions, next steps.
- **Academic defense**: background, research question, method, experiments/results, contribution, limitations, conclusion.
- **Training**: learning goal, concept, walkthrough, examples, exercises, recap.
- **Proposal**: current situation, pain, approach, plan, cost/resources, value, timeline.

Do not overfit every deck to a fixed template. Use the type as a starting point, then adapt to the user's material.

## Slide Types

Build a varied slide sequence. Common types:

- cover
- agenda / contents
- section divider
- thesis / key message
- problem framing
- process / method
- timeline / roadmap
- comparison
- metric dashboard
- chart explanation
- table / matrix
- case or example
- architecture / system diagram
- team / roles
- summary / next steps

Every slide should have one main job. If a slide has two unrelated jobs, split it.

## Visual System

Choose a design direction based on audience and context:

- Executive and board decks: restrained, dense, high contrast, clean charts, strong headlines.
- Investor decks: confident, visual, market-aware, strong story rhythm.
- Academic decks: credible, structured, diagram-friendly, moderate decoration.
- Training decks: clear hierarchy, examples, callouts, repeatable section cues.
- Product decks: benefit-led layout, concise claims, and clear structure.

Avoid one-note palettes. Use a neutral base plus 1-2 accents. Keep enough contrast for projection.

## Layout Rules

- Use large message headlines rather than generic titles when appropriate.
- Left-align body copy unless a page is intentionally centered.
- Keep body text short; move detailed explanation to notes.
- Use table-like grouping, process structure, comparison framing, timelines, and cards for structured information.
- Do not repeat the same two-column layout for every slide.
- Use stable margins and spacing.
- Keep visual elements aligned to a clear grid.
- Avoid decorative accent lines under every title; they make decks feel generic.

## Content Density

Choose density deliberately:

- Board/report decks can carry more information but need stronger hierarchy.
- Sales and pitch decks need fewer words and more visual framing.
- Training decks should leave room for examples and explanation.
- Defense decks need enough evidence but must stay readable from a room.

When source material is long, synthesize. Do not paste paragraphs onto slides.

## Charts and Diagrams

- Pick chart types based on the question: trend, comparison, composition, distribution, relationship, process, or hierarchy.
- Add takeaways near charts. Do not make the audience infer the point.
- Use direct labels where possible.
- Avoid tiny legends and low-contrast gridlines.
- For unsupported exact numbers, use qualitative diagrams rather than fake metrics.

- This bash-only generator does not embed images or icons.
- Use native PPT shapes, cards, accent bars, title hierarchy, and structured text instead.
- Keep every visual element tied to the slide message rather than decoration.
